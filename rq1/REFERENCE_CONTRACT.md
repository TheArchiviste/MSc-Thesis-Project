# Evaluated implementation: rq1-v7

V7 follows the preserved v1/v2 assessor failures. Public task rq1-excerpt-v3 uses readable source, constrained evidence-before-verdict output, an explicit quantity-dependency rule, one non-Qwen API candidate, improved reduced anchors and two assessor-only reserve blocks. All thirty experiment C inputs, Q settings, selector and renderer remain unchanged. Source dependency references are improved before any Q outcome. Obtain fresh v7 CPU receipts; preserve v5/v6 records without relabelling them. See [the declared amendment](../docs/RQ1_V3_AMENDMENT_2026-10-30.md).

This is a bounded audit of the configuration described here. It uses the original pretrained Q weights and a released prompt, with an adapted selector and renderer. It is not a bit-for-bit reproduction of every QCRI runtime component. This decision was made before any real Q outputs or experiment excerpts were inspected.

The renderer is a lexical implementation for the enrolled Juliet C subset, not a general C/C++ parser. It does not add unseen declarations or values merely because they would help explain a flaw. It deliberately restores enclosing guards, because omitted control headers could misrepresent the visible mechanism. The CPU conformance check must exercise the complete selector on local and interprocedural/macro fixtures, retain the guard, and structurally import/map/reset all 30 experiment sources. It does not require main fact coverage. Four additional assessor-only source witnesses support R15/R17; these cases receive no experiment Q queries. The twenty-anchor source-checked calibration gates release for assessment, while independently frozen acquisition may run sealed.

The older repository core at `7023ff49fe7b800e8b26bcae52e2fcdafe95fa9b` is lineage only. Its prompt and function-only renderer are superseded. Its token audit and work locks cannot be reused as rq1-v7 evidence. The unchanged source corpus and finite witnesses remain historical preparation evidence; fresh local acceptance confirms them again without deleting prior files.

`pipeline_contract.json` records the implementation's file hashes, including acquisition, renderer, assessment and reporting code. `verify` rejects drift. Acquisition fingerprints separately bind the Q/Joern dependencies, source/reference inputs and actual stage environment. Judging/reporting code has its own contract and release lock; changing it does not silently invalidate unchanged sealed acquisition. Shared acquisition changes still need a versioned deviation, with affected inputs rerun consistently and earlier records retained. No output-driven case replacement or selector tuning is allowed. Seals detect alteration, not user access.

The [pinned Q model card](https://huggingface.co/QCRI/LLMxCPG-Q/blob/1f48ab60420d90277207394f1254d27d3375b07e/README.md) identifies Qwen2.5-Coder-32B-Instruct as its base. The separate GPT-6 Astra API candidate avoids that model family, without establishing independent training data or independently human-validated judgments. Its suitability remains subject to the declared screen.

The v3 assessment contract binds the public rubric and assumptions into every packet ID. Only first excerpt-only grades, conservatively confirmed by source support, enter the primary result. Reference-informed corrections are secondary. Calibration acceptance, exact messages/raw responses and actual assessor model/settings are receipted; no service identity or stateless isolation is fabricated. See [ASSESSMENT.md](ASSESSMENT.md).

The laptop v3 fixture exposed a Scala type error: `Path.elements` widens the sink union to `AstNode`, whereas the pinned data-flow extension requires `CfgNode`. V4 explicitly collects CFG sink nodes before the backward call and retains `cpg.all` as its source argument. It also interprets structured Scala diagnostics on stdout as failed queries even if the WebSocket envelope says success. Raw stdout remains preserved. This compatibility repair precedes all Q acquisition; see the [repair record](../docs/RQ1_JOERN_FIX_2026-10-30.md).

V5 corrects readiness diagnostics to return a bound string instead of relying on `println` in the RPC response. The audited v4 scan can be recovered only with its exact source contract, unchanged scientific core/environment, all 30 source-scoped raw log markers, the original two successful selector fixtures and one fresh diagnostic probe. The derived receipt retains actual historical execution provenance; no new full scan is claimed. See [recovery details](../docs/RQ1_CPU_RECOVERY_2026-10-30.md).
